## 1. 规划原则（对齐规范评分）

规范 §7.4 的 100 分评分维度，是本规划排期的"北极星"：

| 评分维度 | 分值 | 对应模块 | 本规划中的落点 |
| --- | ---: | --- | --- |
| 任务正确性 | 25 | 全链路 | W3（端到端打通）+ W7（评估收敛） |
| 测试与自评闭环 | 20 | M11 | W7 专项周 + 全程持续 |
| 工作流 / Agent 设计 | 15 | M9 | W5 编排周 |
| 接口、命名与证据 | 15 | M1（已冻结）+ M8 | 全程守契约 + W4 回答生成 |
| 工程与文档 | 15 | M0 + 全程 | 每周收尾同步 spec/doc |
| 演示与个人答辩 | 10 | 全程 | W8 演示准备周 |

三条贯穿性纪律（规范 §5.1/5.2 持续闭环）：
1. **一个模块 = 一个"先测后码"的小闭环**：写清"什么算对" → 补测试 → 最小实现 → 跑测试 → 同步文档。
2. **每个模块结束做一次"三模块串联"**，防止能力层各自为政、最后拼不起来。
3. **本地证据与联网摘要不混写**、**版本不混引**、**确定性规则不交给 LLM**——这三条是失分高发区，贯穿每一周。

## 3. 逐周详细计划

### 第 1 周（W1）— M3 开放获取下载与合规层【收尾当前任务】

**目标**：闭合联网链路"最后一公里"，只下合法开放的 PDF。

- M3-1 合规判断纯函数（`oa_status + license + oa_url → 允许/拒绝+理由`），确定性、不含 LLM
- M3-2 下载执行器（大小上限、超时、`%PDF` 魔数校验、SHA256）
- M3-3 下载编排 `DownloadService`（合规→下载→`DownloadRecord`，单文件失败隔离）
- M3-4 下载记录落库（`download_records` 表）
- M3-5 CLI 验收入口

**验收**：全量 pytest 绿；合规判断为纯函数且拒绝理由可落记录；未授权联网零 HTTP；**M2 检索 → M3 下载 → M5 入库三模块串联演示可一键复现**（实弹、联网）。

**规范对齐**：§2.6 合规边界（不绕过付费墙、无法获取全文只存元数据）；§3.2 下载合规。

---

### 第 2 周（W2）— M4 去重与版本关系识别

**目标**：解决"同一论文多源重复、preprint/会议/期刊版各自成记录"问题。

- 确定性合并：DOI / arXiv ID / 标题+年份 弱键逐级匹配 → 合并为同一 `paper_id`
- 版本族归并：建 `VersionRelation`，识别 preprint → 会议/期刊链条，标记权威版本
- `papers` 表升级支持版本族查询

**验收**：同一论文四源检索合并为 1 条；preprint 与期刊版同族且权威版本可测；全程离线可测（沿用 M2 `fakes.py` 模式）。

**规范对齐**：§2.6「相同论文的预印本、会议版和期刊版必须建立版本关系」；§8 版本关系是错引防护的硬约束。

---

### 第 3 周（W3）— M6 召回与重排【端到端里程碑①】

**目标**：让本地知识库"检索得出来"，为回答生成供料。

- 向量索引：BGE-M3 embedding（本地跑，RTX 4060 8GB 支撑；模型下载复用 M5 的 HF 镜像方案）
- 混合召回：稀疏（关键词）+ 稠密（语义）双路
- 重排：召回结果按相关性排序，产出 `Evidence`（逐字 quote + Locator + 检索分数）

**验收**：召回 `Recall@K` 可测；`Chunk → Evidence` 证据链可回溯；纯语义检索 vs 混合检索的对照实验能跑（为 M11 评估储备数据）。

**规范对齐**：§3.2「参考 PaperQA2 思路，解析/索引/召回/重排/证据验证/答案生成相互分离」；§7.1 的 `Recall@K` 指标。

> ⚠️ 风险点：BGE-M3 在 Python 3.13 的兼容性需本周尽早排雷；若受阻可先以标准库/轻量方案占位召回，不阻塞整体进度。

---

### 第 4 周（W4）— M8 带引用的证据回答生成

**目标**：本地库 → 回答的端到端贯通（第二条链打通）。

- `Claim`（断言 + `evidence_ids` 非空 + 支持等级）→ `Answer`（summary / conflicts / 拒答）
- 引用定位到原文页码/章节，证据来源类型显式标注（全文证据 / 摘要信息 / 模型推断）
- 证据不足时明确拒答（含理由），不得输出无证据断言

**验收**：每条事实可反查到具体页码/章节；无证据断言被契约拒绝；拒答不给答案；三种证据来源类型不混写。

**规范对齐**：§2.4/§2.6 输出与约束；§4 证据链（`Claim.evidence_ids` 非空、摘要不得充当全文证据）；§7.2 教师会检查"能否区分全文证据、摘要信息和模型推断"。

---

### 第 5 周（W5）— M9 Agent 编排与决策（LangGraph）

**目标**：把能力层组装成一个"模型动态选工具"的 Agent。

- LangGraph 图：分析问题 → 查本地库 → 选择本地检索/联网扩展 → 检索/下载/去重/索引 → 召回重排 → 充分性判断 → 作答/继续/拒答
- 停止条件：最大轮次、工具调用数、token/费用上限（对齐规范 §4.3 的 7 状态 + 上限常量）
- 人工确认：写入、下载、执行代码等操作须授权参数

**验收**：两条检索路径可被 Agent 动态选择；教师"关闭联网"和"清空本地库"两种场景均能独立工作；预算超限/停止条件生效。

**规范对齐**：§2.1「Agent 根据问题和覆盖度选择检索路径」；§4.3 任务状态机；§5「写入/删除/发送/下载须人工确认」。

---

### 第 6 周（W6）— M7 证据充分性判断 + M10 检索记录与可追溯

**目标**：补齐"决策开关"与"留痕审计"两块拼图。

**M7 充分性判断**：
- 判断当前证据是否足以回答，不足以则触发继续检索（查询迭代）
- 与 M9 的"继续/作答/拒答"分支打通

**M10 检索记录**：
- 检索式、来源、访问时间、文献标识、处理记录全量留痕
- 结果绑定 `kb_version`，保证可复现

**验收**：充分性判断可测且与 M9 分支联动；每次任务的检索轨迹可审计；"为什么这轮没结果"可追溯。

**规范对齐**：§3.3「必须保存检索式、来源、访问时间、文献标识和处理记录」；§7.2「核对检索记录」。

---

### 第 7 周（W7）— M11 测试与评估闭环

**目标**：把"能跑"变成"可证明能跑对"。

- 构建四类问题集：可回答、需联网补充、不可回答、多跳（规范 §7.1）
- 统计 7 项指标：`Recall@K`、去重准确率、开放全文下载成功率、引用准确率、答案支持率、拒答准确率、单次任务成本
- 失败样例（漏检、错引、错误版本）加入回归集
- 维护固定训练集 / 开发评估集 / 最终保留集，每轮记录数据集版本、代码版本、模型参数、修改前后对比

**验收**：评估报告含数据集版本 + 指标 + 失败样例 + 修改前后对比；无实际运行不声明通过。

**规范对齐**：§7.1 自评指标、§7.3 闭环（失败类型 → 更新内容映射表）。

---

### 第 8 周（W8）— 演示准备与个人答辩

**目标**：可复现 + 可解释 + 文档归档。

- 一键复现演示：固定脱敏数据 + 固定命令，从问题到带引用回答全链路
- 随机代码解释准备：核心模块（合规判断、去重、召回、编排）能讲清"为什么这么设计"
- 文档归档：`已完成任务.md` 逐模块补全、`doc/接口与字段.md` 契约最终一致性复核、`bug调试文档.md` 收口

**验收**：隐藏测试集 + 现场输入 + 结果复算通过；答辩能解释个人贡献。

**规范对齐**：§7.4 演示与答辩（10 分）——"可复现运行、随机代码解释、个人贡献"。

## 5. 每周固定动作（节奏）

每周结束前完成 4 件事，保证"开发、测试、评估、文档同步"（规范 §5.1）：

1. **跑全量测试**：`python -m pytest`，记录通过数；
2. **同步 spec**：更新 `当前开发任务.md` / `未来规划.md` / `已完成任务.md`；
3. **同步 doc**：确认契约/架构变化已进 `doc/`；
4. **记一条进展**：写进项目日志（含本周风险与下周计划）。
