### 来源选择与理由（已冻结）

两层四源，各有不可替代的分工：

| 来源 | 角色 | 主检索 | OA 判定 | 许可证 | 不可替代性 |
| --- | --- | --- | --- | --- | --- |
| OpenAlex | 骨干 | 是 | 是 | 仅代号 | 一次请求即可填满大部分 `PaperRecord` 字段；免费无密钥，带 `mailto` 进 polite pool |
| Crossref | 骨干 | 否 | **否**（恒 `unknown`） | **是** | DOI 注册机构本身，**唯一提供许可证**的源，是 M3 合规下载的依据 |
| arXiv | 补充 | 是 | 是 | 否 | 全文 PDF 来源最好；arXiv ID 是 M4 版本关系的锚点；所有记录恒为 preprint |
| Semantic Scholar | 补充 | 是 | 是（需有 PDF 链接） | 否 | 引用网络扩展 + DOI/arXiv/PMID 跨源 ID 映射 |

明确不接入及其理由：Google Scholar（无官方 API，爬取违反条款）、Sci-Hub（违法）、PubMed / Europe PMC（领域不符）、DBLP（无摘要与 OA 链接，已被 OpenAlex 覆盖）、CORE（留作 M3 下载兜底）。

### 关键设计决策

1. **模板方法而非各自为政**：`SourceAdapter` 基类承担限流、失败封装、字段长度处理、OA 筛选；子类只实现 `build_request` 与 `parse_response`。四个源的行为因此完全一致。
2. **失败与空结果在类型上不可混淆**：`SourceFetchResult` 用 `model_validator` 强制两条——成功时 `raw_count >= len(candidates)`；失败时 `candidates` 必须为空。"把 429 说成没搜到"从类型上被堵死。
3. **未授权联网是一等公民，不是异常分支**：`allow_online=false` 时根本不进入 adapter，零 HTTP 调用；但仍为每个源写一条 `RetrievalRecord`（错误码 `online_disabled`），使"这轮为什么没结果"可见。
4. **确定性检索式，不含模型**：`QueryBuilder` 按"有 keywords 用 keywords，否则用 question"的固定规则生成，可复现、可断言。让模型生成检索式是 M7 的职责。
5. **每源各自翻译查询语法**：四个源的语法与筛选参数完全不同，共用"检索意图"而非硬塞同一个字符串。
6. **OA 判定刻意保守**：只有"上游明确开放"且"拿到可下载链接"才判 `open`；上游说开放却没链接 → `unknown`（没有链接就下不到全文，下不到全文不能作全文证据，不能写 `open` 骗自己）。
7. **密钥零泄漏**：`api_key` 只从外部传入，不落在 `PaperRecord`、`RetrievalRecord`、`warnings` 或日志中；有专门的测试用例断言这一点。
8. **顺序确定**：适配器遍历顺序固定为 `ONLINE_SOURCE_NAMES`，保证检索记录、缓存键与评估结果跨运行可复现。
9. **零新增第三方依赖**：SQLite 用 `sqlite3`、XML 用 `xml.etree.ElementTree`、哈希用 `hashlib`，均为标准库；仅新增 `httpx`（已在 `doc/架构设计.md` 记录）。

### 遗留限制

1. **不做去重**：`SearchOutcome.candidates` 是未去重的跨源汇总，同一论文会在多个源各出现一次。合并与版本族归并属 M4。调用方不得直接当最终清单。
2. **不做合规判断**：适配器只如实上报 `oa_status` / `oa_url` / `license`，是否允许下载由 M3 决定。

6. **限流按进程而非全局**：多进程各自限流会叠加出高于礼仪的请求频率；生产化时需外部化限流。

### 关键设计决策（契约级，已冻结进 doc/接口与字段.md v0.4.0）

1. **`kb_version` 确定性派生**（同文件集+同参数+同解析器=同版本号）：重复入库天然幂等，与"检索结果绑定版本、可复现"承诺一致。
2. **`chunk_id` 派生纳入分块参数**：同一文件用不同 `chunk_size` 入库必然得到不同 ID——chunk size 对照实验的版本隔离基础。
3. **`chunks` 表主键 `(kb_version, chunk_index)`**：不同参数的知识库版本互不覆盖。
4. **Docling 惰性导入 + 鸭子类型注入**：测试不导入 torch/docling（261 例中 Docling 相关 6 例秒级离线跑完）；模型路径解析顺序 `DOCLING_ARTIFACTS_PATH` → `~/.cache/docling/models` → 联网下载。

### 环境踩坑记录（复现价值高）

Docling 首次联网拉模型在国内网络三连败，最终方案：`HF_ENDPOINT=https://hf-mirror.com` + `HF_HUB_DISABLE_XET=1` + `docling-tools models download`。直连 HF 502；镜像站不支持 Xet 存储通道（401）；手动 `hf download` 的快照会缺小配置文件。此方案对 BGE-M3（M6）同样适用。

### 遗留限制

1. **不做 OCR/扫描件**：无文本层 PDF 报 `PARSE_FAILED`；OCR 不在课程范围。
2. **单词粘连未解决**：部分出版 PDF 字符间距信息丢失，pypdf/docling 提取结果存在单词粘连（如 `ADAPTIVEMULTI-TOKENPREDICTION`）；影响分块文本质量，不影响页码定位；docling 换模型/参数可能改善，记入 `spec/bug调试文档.md` 观察。
3. **`KBVersion.built_at` 每次入库刷新**：确定性版本号下重复入库会覆盖 `built_at` 与计数，不影响正确性，但"首次构建时间"语义丢失；如需审计可在 M10 检索记录里补事件。
4. **存储层单进程**：与 M2 缓存同款约束，多进程并发写入未设计。
5. **`ingest_pdfs` Agent 工具未冻结**：写入工具的授权参数设计属 M9。
