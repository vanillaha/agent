## 3. 下一项需要先决定的取舍

M2 完成后，联网链路已能产出候选文献与"能不能下载"的判断依据，但**下游暂时无人消费**。因此有两个都成立的选择：

**选择 A：M5 文档解析与分块索引**（原计划，理由仍成立）

- 理由：引用必须定位到原文（页码/章节/表格），而定位信息在解析阶段产生并一路传递到 `Evidence`。这一层做错，召回、充分性判断、引用回答全部失真，越晚发现返工越贵。
- 好处：先打通"本地库 → 回答"的最短路径，能最早跑通端到端 demo。
- 代价：M2 的产出继续悬着。

**选择 B：M3 开放获取全文下载与合规层**（闭合联网链路）

- 理由：M2 已把 `oa_status` / `oa_url` / `license` 准备齐全，M3 正好接住；且 M3 是"联网搜集"这一课题要求的另一半。
- 好处：联网链路形成闭环（检索 → 下载 → 落到本地文件），M2 的产出即刻有用。
- 代价：下载下来的 PDF 仍要等 M5 才能变成证据，端到端仍跑不通。

**建议**：选 A。端到端跑通的价值高于补齐单条链路的完整性，且 M5 产出的定位信息是整条证据链的地基。但这是需要用户确认的取舍，**确认后再把本节替换为该任务的完整规格**。

## 4. 本文件的使用方式

按 `AGENTS.md`「当前只维护一个开发任务」：

- 任务确认后，把本文件替换为该任务的完整规格（目标、交付物、接口、边界、错误行为、验收标准）。
- 任务完成后，把成果写入 `spec/已完成任务.md`，把下一项写入 `spec/未来规划.md`。
- 契约内容只写在 `doc/接口与字段.md`，本文件引用而不复制。
