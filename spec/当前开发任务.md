## 2. 目标

闭合联网链路的"最后一公里"：给定 M2 产出的 `SourceCandidate`（含 OA 状态、OA 链接、许可证），**先做合规判断、再执行下载**——只下合法开放的 PDF，付费墙一律不碰；下载结果落 `DownloadRecord` 并可审计；无法获取全文时保留元数据与链接（课程规范要求）。

## 4. 接口要点（契约细节冻结在 `doc/接口与字段.md`，此处只列决策）

- 输入复用 M2 的 `SourceCandidate`（`license` 从这里来）；输出复用 M1 的 `DownloadRecord`（`download_id` / `paper_id` / `url` / `status` / `checked_at` / `file_type` / `file_size_bytes` / `sha256` / `failure_reason`）——**不造同义字段**。本地文件路径不进 `DownloadRecord`（契约没有该字段），由存储层 `download_records` 表扩展列持有。
- 下载状态用 M1 枚举 `DownloadStatus`（`DOWNLOADED` / `SKIPPED_NOT_OPEN_ACCESS` / `REJECTED_FILE_TYPE` / `FAILED`）；错误码复用 M1：`DOWNLOAD_FAILED` / `UNSUPPORTED_FILE_TYPE` / `FILE_NOT_FOUND`。
- 合规规则（v1，确定性）：`oa_status` 为开放 且 `license` 在允许清单内 且 `oa_url` 存在 → 允许；否则 **不抛错**，产出 `SKIPPED_NOT_OPEN_ACCESS` 的 `DownloadRecord` 并记录理由（跳过与失败必须区分——枚举 docstring 原话）。允许清单初始值在实现时于 `compliance.py` 顶部常量冻结并写入文档。
- 下载上限常量（大小/超时）进 M1 风格的冻结常量，超限报错不静默截断。
- 下载的 PDF 顺势可喂给 M5 的 `IngestService`——本任务末尾做一次"M2 检索 → M3 下载 → M5 入库"的三模块串联演示（实弹，联网）。

## 5. 边界（本任务不做）

- 不做解析与分块（M5 已完成，直接复用）。
- 不做去重与版本关系（M4）。
- 不做并发抓取、断点续传。
- 不碰付费墙：任何"尝试绕过"的 URL（如 Sci-Hub 镜像）永不进入允许清单。
- 非 PDF 产物（HTML 摘要页等）不落全文，只记录元数据。

## 6. 验收标准

1. 新增用例覆盖正常 / 边界 / 失败 / 安全四类，全量 pytest 绿。
2. **合规判断是纯函数**：相同输入永远相同决定；拒绝时理由可读、可落记录。
3. 未授权联网时零 HTTP 调用（沿用 M2 `fakes.py` 模式）；真实下载只在实弹验证中发生。
4. 下载记录逐字段可审计：谁（URL）、何时、多大、什么许可证、落到哪个路径、SHA256 多少。
5. 超大文件 / 非 PDF 内容 / 断流均报明确错误码，不落损坏文件。
6. 三模块串联演示可一键复现（CLI 命令记录在本文档验收小节）。
7. 契约变化同步进 `doc/接口与字段.md`（新增第 12 节下载契约，变更记录升 v0.5.0）。
