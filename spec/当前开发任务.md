## 4. 接口要点（契约细节冻结在 `doc/接口与字段.md`，此处只列决策）

- `ParsedDocument.full_text` 由各页文本以 `\n\n` 连接；`Chunk.char_start/char_end` 是**全文偏移**；`Locator.page_from/page_to` 由偏移→页码映射得出（一个 chunk 跨页时填跨页区间）。
- 分块策略名固定 `fixed-v1`：优先在段落/空白边界切，超长段落硬切；`overlap < chunk_size`（`KBVersion` 校验器已有此约束）。
- `chunk_id` 使用 `ids.py` 的确定性 ID（输入：`source_file_sha256` + `chunk_index`），重建同一文件得到相同 ID。
- 错误码复用 M1：`FILE_NOT_FOUND` / `UNSUPPORTED_FILE_TYPE` / `PARSE_FAILED` / `INDEX_FAILED`，不新增枚举。
- 解析失败**不得产出空 Chunk 冒充成功**；无文本层 PDF 返回 `PARSE_FAILED` 并在 `details` 说明。

## 5. 边界（本任务不做）

- 不做向量化与召回（M6）。
- 不做联网下载（M3）。
- 不做 OCR / 扫描件（第一版只处理文本层 PDF）。
- 不做语义分块、按句子对齐等高级策略（chunk size 对照实验在 M6 之后插入）。

## 6. 验收标准

1. 新增用例覆盖正常 / 边界 / 失败 / 安全四类，全量 pytest 绿。
2. 每个 `Chunk.locator` 的页码可回溯到样例 PDF 的真实页码；`full_text[char_start:char_end] == chunk.text`。
3. 相邻 chunk 有 overlap；`chunk_overlap < chunk_size` 违例被拒。
4. 解析失败返回明确错误码，不产出空 Chunk。
5. fixtures 脱敏、测试零公网；同一 PDF 重复入库产生相同 `chunk_id` 集合。
6. 契约变化同步进 `doc/接口与字段.md`（新增第 9 节 ingest 模型）。
