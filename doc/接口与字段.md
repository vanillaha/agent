| 前缀 | 含义 | 前缀 | 含义 |

格式校验：`<前缀>_` 后跟 3—64 位 `[A-Za-z0-9_-]`，且首位为字母或数字。

### 标识生成规则（M2 起共用）

本项目有两类标识，用途不同，**不得混用**：

| 类别 | 生成函数 | 摘要长度 | 适用范围 | 为什么 |
| --- | --- | --- | --- | --- |
| 随机标识 | `random_id(prefix)` | 16 位十六进制 | 事件、检索记录等只要求库内唯一即可的对象 | 无需跨运行对齐 |
| 确定性标识 | `deterministic_id(prefix, *parts)` | 16 位十六进制（sha256 前缀） | **文献**等要求跨运行一致的对象 | 同一论文无论从哪个源、哪一轮得到，都必须派生出同一个 `ppr_` 标识，否则检索记录、证据链与评估无法跨运行对齐 |
| 完整摘要 | `sha256_hex(text)` | 64 位小写十六进制 | 缓存键等需要完整摘要的场合 | 符合 `Sha256` 类型约束 |

- 确定性标识的组成部件用 `\x1f` 分隔（不可见控制符），避免 `a|b` 与 `a/b` 被算成同一个键；部件不得为空。
- 文献标识的规范键优先级：**DOI > arXiv ID > 标题+年份**。三者皆缺则拒绝入库，**不接受无标识记录**。
- `SourceCandidate.upstream_id` 是**上游自己的主键**（如 OpenAlex 的 `W2741809807`），不是本项目标识，因此不适用前缀规则，仅作溯源用途。

### 开放获取判定规则（M2 起共用）

`resolve_oa_status()` 是全项目"能不能下载"的**第一道闸门**，规则刻意保守：

| 上游说法 | 有可下载链接 | 判定 | 理由 |
| --- | --- | --- | --- |
| 明确开放 | 有 | `open` | 唯一可判定为开放的情形 |
| 明确开放 | 无 | `unknown` | 没有链接就下不到全文；下不到全文不能作全文证据，不能写 `open` 骗自己 |
| 明确封闭 | 无 | `closed` | 上游明确封闭 |
| 明确封闭 | 有 | `unknown` | 上游自相矛盾，宁可保守也不凭猜测下载 |
| 未表态 | 有 | `unknown` | 仅见链接不等于授权 |
| 未表态 | 无 | `unknown` | 无信息 |

判定依据必须落进 `SourceCandidate.oa_evidence`，能回答"凭什么判定它能下载"。非 `http(s)` 开头的链接一律视为无效链接。

## 2. 统一信封（Envelope）

所有接口响应都套在同一个信封里。字段位置与名称固定，不得改名、不得增删同义字段。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `request_id` | string | 是 | 请求标识，用于串联日志 |
| `task_id` | string | 是 | 任务标识 |
| `run_id` | string | 是 | 本次运行标识（同一任务重跑会产生新 run） |
| `status` | enum | 是 | 任务状态，取值见第 3 节 |
| `data` | object\|null | 否 | 接口负载，类型随接口而变 |
| `evidence` | array | 否 | 本次响应涉及的证据 |
| `datasets` | array | 否 | 涉及的数据集与版本 |
| `artifacts` | array | 否 | 产物 |
| `warnings` | array | 否 | 非致命告警 |
| `events` | array | 否 | 事件流 |
| `error` | object\|null | 否 | 错误，仅 `status=failed` 时出现 |

一致性规则（违反即报错）：

- `status = failed` 时 `error` 必填；其他状态 `error` 必须为空。

数组字段的元素类型：`evidence` → `Evidence`，`datasets` → `DatasetRef`，`artifacts` → `Artifact`，`warnings` → `WarningItem`，`events` → `Event`。

## 3. 任务状态（`TaskStatus`）

| 状态 | 含义 | 终态 |
| --- | --- | --- |
| `queued` | 已创建，等待执行 | 否 |
| `running` | 执行中 | 否 |
| `waiting_for_input` | 等待人工确认或补充信息 | 否 |
| `cancel_requested` | 已收到取消请求，尚未停止 | 否 |
| `succeeded` | 成功完成（**拒答也算成功**） | 是 |
| `failed` | 失败，必须带 `error` | 是 |
| `cancelled` | 已取消 | 是 |

不得另设同义状态（例如 `done`、`error`、`pending`、`aborted` 均为非法值）。

状态转换：

```text
queued → running → {succeeded | failed | cancelled}
running → waiting_for_input → running
running → cancel_requested → cancelled
```

## 4. 错误码

| 错误码 | 触发场景 |
| --- | --- |
| `invalid_request` | 请求字段不合法 |
| `file_not_found` | 指定的本地文件不存在 |
| `unsupported_file_type` | 文件类型不在支持范围 |
| `local_kb_unavailable` | 本地知识库或索引不可用 |
| `online_disabled` | 请求要求联网但未获授权 |
| `upstream_unavailable` | 外部数据源不可用 |
| `rate_limited` | 触发数据源限流 |
| `not_open_access` | 文献无合法开放全文 |
| `download_failed` | 下载失败 |
| `parse_failed` | 文档解析失败 |
| `index_failed` | 建索引失败 |
| `evidence_insufficient` | 证据不足且已无继续检索余地 |
| `budget_exceeded` | 超出 token / 费用预算 |
| `tool_call_limit_exceeded` | 超出工具调用次数上限 |
| `cancelled` | 被取消 |
| `internal_error` | 未归类的内部错误 |

错误结构与公共字段：

```text
error.code     错误码（见上表）
error.message  人可读说明，1—1000 字符
error.details  结构化补充信息
```

## 6. 领域模型

### 6.1 `Locator` — 证据位置

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `page_from` | int\|null | 否 | ≥1 |
| `page_to` | int\|null | 否 | ≥1，且不得小于 `page_from` |
| `section_path` | string[] | 否 | 章节层级，如 `["3 Method","3.2 Data"]` |
| `table_id` | string\|null | 否 | 表格标识 |
| `figure_id` | string\|null | 否 | 图标识 |
| `char_start` / `char_end` | int\|null | 否 | ≥0；`char_end` 必须大于 `char_start` |

约束：**必须至少提供页码或章节路径之一**，否则证据无法回溯，视为无效证据。

`to_display()` 输出人可读位置，例如 `p.3, 3 Method > 3.2 Data`，用于回答中的引用标注。

| 字段 | 类型 | 必填 | 说明 |

| `title` | string | 是 | 标题，≤256 |
| `authors` | string[] | 否 | 按出现顺序去重 |
| `year` | int\|null | 否 | 1800—2200 |
| `venue` | string\|null | 否 | 期刊或会议 |
| `doi` | string\|null | 否 | 归一化：去 URL 前缀并转小写 |
| `arxiv_id` | string\|null | 否 | arXiv 标识 |
| `abstract` | string\|null | 否 | 摘要，≤2000 |

| `oa_status` | enum | 否 | 默认 `unknown` |

### 6.3 `VersionRelation` — 版本关系

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `group_id` | `vgr_` | 是 | 版本族 |
| `paper_id` | `ppr_` | 是 | 文献 |

### 6.4 `Chunk` — 原文分块

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `chunk_id` | `chk_` | 是 | 分块标识 |
| `paper_id` | `ppr_` | 是 | 所属文献 |
| `kb_version` | `kb_` | 是 | 所属知识库版本 |

### 6.5 `Evidence` — 证据（核心）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `evidence_id` | `evd_` | 是 | 证据标识 |
| `source_type` | enum | 是 | `fulltext` / `abstract` / `metadata` / `inference` |
| `source_name` | enum | 是 | 来源 |
| `paper_id` | `ppr_` | 是 | 所属文献 |
| `chunk_id` | `chk_`\|null | 条件 | **全文证据必填** |
| `quote` | string | 是 | **逐字引用**，不得改写 |
| `locator` | `Locator` | 是 | 原文位置 |
| `is_local` | bool | 是 | 是否来自本地全文 |
| `retrieval_score` | float\|null | 否 | 0—1 |
| `retrieval_round` | int | 是 | ≥0，第几轮检索得到 |
| `retrieved_at` | datetime | 是 | UTC |

关键约束：

- `source_type = fulltext` → `chunk_id` 必填且 `is_local` 必须为 `true`。
- `source_type = inference` → `is_local` 必须为 `false`。
- 这两条共同保证：**联网搜到的摘要不会被当成全文证据，模型推断不会伪装成本地证据。**

`ConflictPair`：`evidence_ids`（≥2 条）、`description`。

`Answer`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

## 7. 请求与任务视图

### 7.1 `PaperQARequest`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `request_id` | `req_` | — | 必填 |
| `requested_at` | datetime | — | 必填，UTC |
| `question` | string | — | 必填，≤2000 |
| `keywords` | string[] | `[]` | 关键词 |
| `domain` | string\|null | `null` | 领域 |
| `doc_types` | enum[] | `[]` | 文献类型筛选 |
| `year_from` / `year_to` | int\|null | `null` | 1800—2200，`year_from ≤ year_to` |
| `local_pdf_paths` | string[] | `[]` | 待入库本地 PDF，最多 200 个 |
| `kb_version` | `kb_`\|null | `null` | 指定使用的知识库版本 |
| `allow_online` | bool | `false` | **默认禁止联网** |
| `max_rounds` | int | `3` | 1—5 |
| `max_downloads` | int | `5` | 0—50 |
| `max_tool_calls` | int | `30` | 1—200 |

> M2 的模型是**联网链路的内部契约**，不直接对外暴露为 REST 响应，但它决定

### 8.1 来源选择（四个源的分工）

| 来源 | 角色 | 主检索 | 开放获取判定 | 许可证 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `openalex` | 骨干 | 是 | 是（`best_oa_location`） | 仅代号 | 一次请求即可填满大部分 `PaperRecord` 字段 |

### 8.3 `SourceRequest` / `ParsedPage` / `SourceCandidate`

**`SourceRequest`**（一次 HTTP 请求的完整描述，便于测试断言"请求拼得对不对"）

| 字段 | 类型 | 必填 | 约束 |

| `params` | `dict[str, Any]` | 否 | 默认空字典 |
| `headers` | `dict[str, str]` | 否 | 默认空字典 |

**`ParsedPage`**（解析结果，adapter 内部使用）

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `candidates` | `SourceCandidate[]` | 否 | 默认空列表 |

| `warnings` | `WarningItem[]` | 否 | 默认空列表 |

**`SourceCandidate`** —— 单篇候选 = M1 的 `PaperRecord` + 上游溯源信息。**只补 M1 确实没有的字段，不重造已有字段。**

### 8.4 `SourceFetchResult` — 单源一次检索的结果

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| `source_name` | `SourceName` | 是 | 见第 5 节 | 来源标识 |
| `query` | `SourceQuery` | 是 | — | 实际执行的检索请求 |
| `candidates` | `SourceCandidate[]` | 否 | 默认空列表 | 归一化后保留的候选 |
| `raw_count` | `int` | 否 | `>= 0`，默认 0 | 上游返回条数 |
| `request_url` | `str \| null` | 否 | 长度 ≤2048 | 真实请求地址（含 `from_cache` 时的原始地址） |
| `from_cache` | `bool` | 否 | 默认 `false` | 是否命中响应缓存 |
| `retry_count` | `int` | 否 | `>= 0`，默认 0 | HTTP 层重试次数 |
| `duration_ms` | `int` | 否 | `>= 0`，默认 0 | 耗时（毫秒） |
| `skipped_count` | `int` | 否 | `>= 0`，默认 0 | 字段不合法被跳过的条数，等于 `raw_count - len(candidates)` |
| `warnings` | `WarningItem[]` | 否 | 默认空列表 | 告警 |
| `error` | `ErrorInfo \| null` | 否 | 默认 `null` | 失败原因；`null` 表示成功（**空结果也算成功**） |

派生属性：`ok`（`error is None`）。

**强制校验（由 `model_validator` 保证，不允许绕过）**：

1. `error is None` 时 `raw_count >= len(candidates)`——解析结果不可能多于上游返回。
2. `error is not None` 时 `candidates` 必须为空——**不允许把失败伪装成部分成功**。

因此"检索失败"与"检索成功但没有结果"在类型上可区分：前者 `error` 非空，后者 `error` 为空且 `raw_count == 0`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `candidates` | `SourceCandidate[]` | 否 | **跨源汇总，未去重**——同一论文可能在多个源各出现一次，合并与版本关系判定属 M4 |

### 8.7 冻结的告警码

| 告警码 | 触发条件 | 含义 |
| --- | --- | --- |
| `mailto_missing` | 需要邮箱的源未配置 `mailto` | 会落在公共请求池，响应可能变慢或被限流 |
| `open_access_filter_local` | 源不支持服务端 OA 筛选但要求了 OA | 已本地过滤，`details.dropped` 给出丢弃条数 |
| `records_skipped` | 上游有记录因字段不合法被跳过 | `details.skipped` 给出条数；上游给了但我们不敢用 |
| `field_truncated` | 标题/摘要/会议名超长被截断 | `details` 给出字段名、原长度、上限；**不静默改数据** |
| `source_failed` | 某个源检索失败 | 单源失败不中断整轮，`details.error_code` 给出错误码 |
| `no_source_selected` | 没有可用的在线来源 | 本轮未检索 |
| `online_disabled` | 未授权联网 | 仅使用本地知识库检索 |

### 8.8 冻结的错误码映射

| 异常 | 错误码 | 触发场景 |
| --- | --- | --- |
| `OnlineDisabledError` | `online_disabled` | 未授权联网时仍尝试发请求（防御性） |
| `RateLimitedError` | `rate_limited` | 上游 429 且重试耗尽，或本地限流器拒绝 |
| `UpstreamError` | `upstream_unavailable` | 上游返回错误状态或网络层失败 |
| `ResponseShapeError` | `upstream_unavailable` | 响应可取得但结构不符（单独成类便于分流"上游挂了"与"上游改格式了"） |
| 其他未预期异常 | `internal_error` | 适配器代码缺陷；**不得伪装成上游不可用**，`details.exception` 记异常类名 |

### 8.9 冻结的行为契约

| 契约 | 内容 |
| --- | --- |
| 未授权不联网 | `request.allow_online = false` 时**不发起任何 HTTP 请求**；仍为每个来源写一条 `RetrievalRecord`，错误码 `online_disabled` |
| 单源失败隔离 | 任一源失败、被限流或改格式，其余源照常返回；失败信息只落该源自己的 `RetrievalRecord.error` |
| 失败 ≠ 空结果 | 见 8.4 的两条强制校验 |
| 密钥不外泄 | `api_key` 不得出现在 `PaperRecord`、`RetrievalRecord`、`warnings` 或日志中 |
| 顺序确定性 | 适配器遍历顺序固定为 `ONLINE_SOURCE_NAMES`，保证检索记录、缓存键、评估结果可复现 |
| 失败不静默 | 字段截断、记录跳过、本地 OA 过滤一律产出告警，不悄悄改数据 |
| 限流先于请求 | 限流在发请求**之前**执行，不是"发出后补救" |

### 10.1 `search_papers_online`（M2 冻结）

| 项 | 内容 |
| --- | --- |
| 用途 | 在联网文献源上检索候选文献，返回**未去重**的跨源候选与逐源检索记录 |
| 输入 | ① `PaperQARequest`：`question`、`keywords`、`year_from`/`year_to`、`doc_types`、`allow_online` 与请求级预算等字段 |
| | ② 可选 `query_text`：显式指定本轮检索式（M7 迭代时给新角度用）；不传则由 `QueryBuilder` 按"有 keywords 用 keywords，否则用 question"的确定性规则生成 |
| | ③ 可选 `open_access_only`（默认 `false`） |
| | ④ 可选 `sources`：限定本轮只唤醒哪几个源（如只扩展引用网络时只叫 `semantic_scholar`） |

| 副作用 | 只读。不写本地知识库、不下载文件、不修改任何持久状态（响应缓存除外，且缓存不改变返回语义） |
| 授权要求 | 依赖 `request.allow_online`；为 `false` 时**零网络调用**，返回 `online_disabled = true` 的正常结果 |

| 幂等性 | 同一输入 + 同一缓存状态 ⇒ 同一输出；适配器遍历顺序固定（见 8.9） |
| 不确定性来源 | 上游数据随时间变化、限流、网络；这些都不改变"失败与空结果可区分"的契约 |

| `IngestRequest` | `files[≥1 个 Path]` / `options` | — |
| `PaperIngestResult` | `paper_id` / `source_path` / `source_file_sha256` / `page_count` / `chunk_count(≥1)` | `paper_id` 为内容 SHA256 派生的确定性 `ppr_` 标识 |
| `PaperIngestFailure` | `source_path` / `code` / `message` / `details` | 单文件失败被隔离，不中断批次 |
| `IngestResult` | `papers[]` / `failures[]` / `chunks[]` / `kb_version` | 全部文件失败时抛 `IngestError`，不产出空成功 |

### 11.2 分块与定位

- `Chunk.char_start/char_end` 是 **`full_text` 全文偏移**；不变式：`full_text[char_start:char_end] == chunk.text`。
- `Locator.page_from/page_to` 由偏移→页码映射得出；`overlap=0` 时切点落在页间边界，chunk 不跨页。
- `chunk_id = deterministic_id("chk", source_file_sha256, "fixed-v1:{chunk_size}:{chunk_overlap}", chunk_index)`——同一 PDF 同参数重复入库得到相同 `chunk_id` 集合；**不同分块参数必然得到不同 ID**（避免跨版本主键冲突）。
- 切分顺序：段落边界 `\n\n` > 换行 > 空格 > 硬切；边界切点必须落在 `start + overlap` 之后，防止围绕同一边界产出重复碎片；文档尾部完全落在上一块 overlap 区内时不单独成块。
- 空文档（无可提取文本）抛 `PARSE_FAILED`，绝不产出空 chunk。

### 11.3 错误码（复用第 4 节，无新增）

`FILE_NOT_FOUND`（文件不存在）/ `UNSUPPORTED_FILE_TYPE`（非 .pdf）/ `PARSE_FAILED`（解析失败或无文本层）/ `INDEX_FAILED`（无文件可入库）。

### 11.4 入库工具（预留给 M9）

`ingest_pdfs` 属**写入**工具（落库、写文件），接入 Agent 时必须携带显式授权参数——与第 10 节工具纪律一致。

### 11.5 文本规整（textnorm）

位置：`ingest/textnorm.py`，纯函数 `normalize_text(raw) -> str`，pypdf/Docling 解析器在返回页文本前统一调用。规则（顺序敏感）：

1. 统一换行符 `\r\n`/`\r` → `\n`；
2. 行尾断词修复：段落内 `predic-\ntion` → `prediction`（仅限单个 `\n`；跨段落的 `-\n\n` 是列表/缩写等真实内容，不合并）；
3. 段落内视觉换行合并为空格；段落边界 `\n\n` 保留（分块器首选切点依赖它）；
4. 折叠连续空白、去行首尾空白。

背景：出版 PDF 为排版格式，pypdf 在每个视觉行末插入 `\n`，不规整会污染分块切点（chunk 被提前切短）。

### 11.6 解析器

`Parser` 协议：`parse(path) -> tuple[list[list[str]], parser_name, parser_version]`（每页一组文本块；页码即页序，必须从 1 连续）。

| 实现 | 位置 | 适用 | 说明 |
| --- | --- | --- | --- |
| `PypdfParser`（`pypdf`） | `ingest/pypdf_parser.py` | 常规文本层 PDF | 轻量零模型；缺 `%PDF` 魔数报 `UNSUPPORTED_FILE_TYPE` |
| `DoclingParser`（`docling`） | `ingest/docling_parser.py` | 复杂版式（双栏/公式/表格） | **惰性导入**（未安装报 `PARSE_FAILED`）；按 `provenance.page_no` 归组，无归属项跳过，纯图页空文本占位保证页码连续；模型路径解析顺序：`DOCLING_ARTIFACTS_PATH` 环境变量 → `~/.cache/docling/models`（`docling-tools models download` 的落点）→ docling 自行联网下载 |

CLI（`python -m paper_evidence_qa.ingest.cli`）：`--parser pypdf|docling`、`--chunk-size`、`--chunk-overlap`、`--db <sqlite路径>`（落库，幂等）。

### 11.7 本地知识库存储（KBStore）

位置：`storage/kb_store.py`。标准库 `sqlite3`，schema 由代码创建。三张表：

| 表 | 主键 | 要点 |
| --- | --- | --- |
| `kb_versions` | `kb_version` | 冻结 `KBVersion` 全字段 |
| `papers` | `paper_id`（内容 SHA256 派生） | `source_file_sha256` 唯一——同一文件只一行，重复入库 upsert 更新 |
| `chunks` | `(kb_version, chunk_index)` | 不同分块参数的知识库版本互不覆盖；`page_from/page_to` 从 `Locator` 展开 |

**确定性版本派生**：`kb_version = deterministic_id("kb", chunk_strategy, chunk_size, chunk_overlap, parser_name, parser_version, *sorted(文件摘要))`——同文件集+同参数+同解析器=同版本号，重复入库天然幂等。

读取接口：`load_kb(kb_version) -> (KBVersion, list[Chunk])`（版本不存在抛 `KeyError`）、`list_kb_versions()`、`list_papers()`、`get_paper(sha256)`。
