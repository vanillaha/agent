# 评估设计

## 1. 原则

1. **先定"什么算对"，再写代码。** 每个模块任务开始前先确定评估集与指标。
2. **评估集必须版本化。** 每次评估记录数据集版本、代码版本、模型与参数。
3. **失败样例必须进入回归集。** 漏检、错引、错误版本识别都要固化下来。
4. **不修改确定性规则去迁就模型。** 模型不稳定时收紧结构化约束、增加失败样例。
5. **没有实际运行，不得声明评估通过。**

## 2. 数据集划分

| 数据集 | 用途 | 说明 |
| --- | --- | --- |
| 固定训练集 | 开发时反复使用 | 允许查看答案，用于快速迭代 |
| 开发评估集 | 阶段评估 | 可以查看，但结果必须记录 |
| 最终保留集 | 验收前一次性使用 | 开发期间不查看，避免调参过拟合 |

## 3. 问题集设计（S01 核心）

评估集按四类问题构建，每类都要同时包含可答与不可答的样本：

| 类型 | 说明 | 期望行为 |
| --- | --- | --- |
| 可回答 | 本地库内即可找到支撑证据 | 作答，且引用指向正确的页码/章节 |
| 需联网补充 | 本地库覆盖不足，需联网检索并下载开放全文 | 先联网补充，再作答并标注来源类型 |
| 不可回答 | 领域内确实没有支撑证据 | **拒答**，并说明缺少什么 |
| 多跳 | 需要跨多篇文献、多块证据综合 | 综合作答，各条事实分别引用 |

配套的两种"受控削弱"测试（对应教师现场测试）：

- **关闭联网**：`allow_online=false` 时，需联网补充类问题必须转为拒答，不得编造。
- **清空局部本地库**：删掉部分文档后，原本可回答的问题应转为"证据不足"，而不是继续使用不存在的证据。

## 4. 指标

### 4.1 检索质量

| 指标 | 定义 | 负责模块 |
| --- | --- | --- |
| `Recall@K` | 标注的相关文献中，出现在 Top-K 结果里的比例 | M2、M6 |
| `P@K` / `NDCG@K` | Top-K 的精确率与排序质量 | M6 |
| 去重准确率 | 人工标注的"同一论文"分组与系统分组的 pair-wise 一致率 | M4 |
| 版本识别准确率 | 预印本/会议版/期刊版是否被正确归入同一版本族 | M4 |

#### 4.1.1 M2 已可产出的中间指标

M2 的 `RetrievalRecord` 已经记下了端到端指标所需的原始计数，因此以下指标在 M2 阶段即可计算，无需等 M11：

| 指标 | 定义 | 数据来源 |
| --- | --- | --- |
| 上游字段利用率（解析保留率） | `kept_count / result_count`——上游给了多少，我们敢用多少 | `RetrievalRecord.result_count` / `kept_count` |
| 逐源解析质量 | 按 `source_name` 分组的上一条指标 | 同上，按 `source_name` 聚合 |
| 字段截断率 | 出现 `field_truncated` 告警的记录比例 | `SearchOutcome.warnings` |
| 单源失败率 | `failed_sources` / 参与检索的源数（**不等于"零结果率"**） | `SearchOutcome.failed_sources` |
| 跨源重复率 | M2 汇总候选条数 / M4 去重后条数——直接量化 M4 的价值 | M2 与 M4 对比 |
| 缓存命中率 | `from_cache = true` 的记录比例。**评估时必须排除缓存干扰**：同一检索式重复评估会全部命中缓存，指标会虚高 | `SourceFetchResult.from_cache` |

> 注意：`kept_count < result_count` 不一定是坏事（可能只是上游返回了大量缺标题的记录），但**这个差值必须被看见**。它是"上游数据质量 + 我们解析健壮性"的联合指标。

### 4.2 获取合规性

| 指标 | 定义 | 负责模块 |
| --- | --- | --- |
| 开放全文下载成功率 | `downloaded` 数量 / 尝试下载数量 | M3 |
| 越界下载数 | 对非开放文献发起下载的次数（期望恒为 0） | M3 |
| 元数据降级正确率 | 无开放全文时正确降级为"只存元数据与链接"的比例 | M3 |

### 4.3 回答质量

| 指标 | 定义 | 负责模块 |
| --- | --- | --- |
| 引用准确率 | 回答中的引用是否真的指向支持该事实的原文位置 | M8 |
| 答案支持率 | 事实断言中被证据支持的比例 | M8 |
| 来源类型标注正确率 | 全文证据与摘要信息是否被如实标注 | M8 |
| 拒答准确率 | 不可回答问题正确拒答的比例 | M7、M8 |
| 过度拒答率 | 可回答问题被错误拒答的比例 | M7、M8 |
| 无依据结论数 | 找不到证据支持的结论条数（期望恒为 0） | M8 |

### 4.4 系统指标

| 指标 | 定义 |
| --- | --- |
| 任务成功率 | `succeeded` 任务数 / 总任务数 |
| 结构化输出有效率 | 通过 schema 校验的响应比例 |
| 检索轮次分布 | 每个任务实际消耗的轮次 |
| 单次任务成本 | token 用量、工具调用次数、耗时 |

## 5. 评估记录模板

```markdown
## 评估 <编号> <日期>

- 数据集版本：<版本>
- 代码版本：<commit 或版本号>
- 模型与参数：<模型名、温度、最大轮次等>
- 评估范围：<模块与问题类别>

| 指标 | 修改前 | 修改后 | 是否回归 |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

- 失败样例：（问题编号、输入、期望、实际、错误分类）
- 处理决定：（更新规格 / 更新 fixture / 更新规则与测试 / 收紧模型约束）
```

## 6. 失败分类

| 失败类型 | 更新内容 |
| --- | --- |
| 需求或边界不清 | 更新当前任务与验收标准 |
| 数据缺失或标注错误 | 更新数据说明、fixture 与评估集版本 |
| 规则错误 | 更新规则说明、单元测试与实现 |
| 工具选择或参数错误 | 更新工具 schema、轨迹测试与 Agent 指令 |
| 模型输出不稳定 | 收紧结构化约束、增加失败样例 |
| 状态或接口错误 | 更新状态机、契约测试、实现与接口文档 |
| 安全问题 | 先停止相关能力，更新权限规则与对抗测试 |
